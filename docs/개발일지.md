## 결정과 이유

- **DBC 엑셀은 열 매핑 단계를 거칩니다.** 수강생 DBC 엑셀의 열 구성을 아직 모릅니다(기획서 10장 1번). 시트·머리행·열(메시지 ID·이름·주기·DLC·송신 ECU)을 화면에서 고르게 하고, 열 이름으로 미리 짐작해 둡니다. 「신호 길이(bit)」 같은 열을 DLC 로 잘못 잡지 않도록 「신호·bit」가 들어간 열 이름은 DLC 후보에서 뺍니다.
- **DBC 엑셀은 신호마다 한 줄인 표를 가정해 메시지 단위로 합칩니다.** 같은 메시지 ID 줄은 하나로 합치고, 빈 칸은 뒤 줄 값으로 채우며, 값이 서로 다르면(예: 주기 10 / 20) 처음 값을 쓰고 「충돌」로 알립니다. 메시지 ID 칸이 빈 줄은 병합 셀 아래의 신호 줄로 보고 건너뜁니다.
- **ID 표기는 16진수가 기본이고 10진수를 고를 수 있습니다.** `0x` 접두·`h` 접미가 붙은 값은 설정과 관계없이 16진수로 읽습니다. 0x7FF 를 넘는 ID 는 확장(29비트) ID 로 보고 8자리로 표시합니다.
- **TRC 파서는 PEAK PCAN 계열 공개 형식(버전 1.0~2.1)을 따릅니다.** 머리말의 `$FILEVERSION`·`$COLUMNS` 가 있으면 그대로 따르고, 없으면 첫 데이터 줄 모양으로 버전을 짐작합니다(화면에 「머리말/짐작」 표시). 길이 표기와 실제 바이트 수가 다른 줄은 깨진 줄로 보고 「읽지 못한 줄」로 줄 번호와 함께 보여 줍니다.
- **에러·원격·상태 줄은 건수만 셉니다.** 기획서 10장 4번에서 「CRC 오류」가 응용 CRC 인지 버스 에러 프레임인지 확인이 필요해, 1단계에서는 에러 프레임을 판정하지 않고 참고 건수로만 보고서에 넣었습니다.
- **전송 주기 판정은 연속 프레임 간격 하나하나를 봅니다.** 간격이 `DBC 주기 × (1 ± 허용 오차%)` 를 벗어나면 이탈 1건으로 셉니다. 경계값(정확히 ±허용 오차)은 이탈이 아닙니다. 김(늦음·누락 의심)과 짧음(빠름)을 나누고, 이탈 구간마다 앞·뒤 프레임 시각과 로그 줄 번호를 남겨 원본 로그에서 바로 찾을 수 있게 했습니다.
- **통계 정의** — 평균 주기 = (마지막 시각 − 첫 시각) ÷ (프레임 수 − 1), 지터 = 가장 긴 간격 − 가장 짧은 간격. 화면과 보고서에 정의를 적었습니다.
- **허용 오차는 사용자 설정입니다.** 처음 값 10%는 화면이 비지 않게 넣은 임시값이며, 화면에 「사내 기준으로 바꾸세요」라고 적었습니다(기획서 10장 5번).
- **DBC 주기가 빈 메시지는 주기 검사에서 뺍니다**(이벤트 전송 등). 프레임이 1개뿐인 ID 도 주기를 판정할 수 없어 따로 표시합니다. 둘 다 「이상」으로 세지 않습니다.
- **로그에 채널이 여럿이면 채널을 골라 검사**할 수 있게 했습니다. 채널마다 DBC 가 다를 수 있기 때문입니다.
- **TRC 로그는 저장하지 않습니다.** 로그는 크기가 커서 브라우저 저장 한도(보통 5MB)를 곧 넘습니다. DBC 기준표와 설정만 저장하고, 로그는 새로 열 때 다시 선택합니다.
- **스크립트를 ES module 이 아닌 일반 스크립트로** 불러옵니다. `index.html` 을 파일로 열면(file://) 브라우저가 module 스크립트를 막기 때문입니다.
- **AI 기능은 넣지 않았습니다.** 기획서에서 AI 요약은 확장(3단계)이고, 1단계 검사는 규칙 계산이라 AI 가 필요 없습니다.

## 가정

- TRC 로그는 PEAK PCAN 계열 형식이라고 가정했습니다(기획서 3장). 다른 로거(Vector ASC 등)라면 파서를 추가해야 합니다.
- TRC 시각 열은 ms 단위의 기록 시작 기준 시각으로 봅니다(공개 형식 기준).
- DBC 엑셀은 한 시트에 메시지·신호가 함께 있는 표로 가정했습니다. 메시지 시트와 신호 시트가 따로 있으면 메시지 시트를 골라 쓰면 됩니다.
- DLC 칸은 `8`, `8 byte`, `8바이트` 모양만 받습니다. 다른 표기면 「읽지 못한 줄」로 알립니다.
- 방향(Rx/Tx)은 구분하지 않고 모두 검사합니다.

## 수강생 실제 자료가 있어야 하는 것

1. DBC 엑셀 샘플(열 구성·시트 구성) — 열 짐작 규칙과 합치기 규칙 확인
2. TRC 로그 샘플(파일 앞부분 20줄 정도면 충분) — 로깅 프로그램·버전, 확장 ID·CAN FD 사용 여부
3. 실제로 오류가 있었던 로그 1건과 그 오류 내용 — 도구가 잡는지 확인
4. 「CRC 오류」의 뜻(응용 CRC 인지 버스 에러 프레임인지)과, 응용 CRC 라면 메시지별 위치·다항식·초기값·범위
5. 전송 주기 허용 오차 사내 기준, Alive Counter 사용 여부
6. 제조사별로 DBC 와 다른 부분의 실제 예시, 기존 보고서 양식
7. 로그 1개 파일의 일반적인 크기 — 50만 줄 로그를 Node 에서 읽는 데 약 5초 걸렸습니다. 이보다 크면 코랩·로컬 Python 판을 검토합니다(기획서 7장).
